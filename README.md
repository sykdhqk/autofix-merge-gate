# Autofix Merge Gate

[中文说明](README.zh-CN.md)

Autofix Merge Gate is a reusable review Skill for security teams, repository maintainers, and developers who receive pull requests generated by an AI coding agent. It turns a pull request packet into an alert-by-alert merge decision with explicit evidence states, scanner and behavioral validation, scope-risk checks, accountable owners, and rollback requirements.

The project supports [iPolloWork](https://github.com/Devin-AXIS/iPolloWork) through a directly importable `.ipollowork-plugin` package. It also ships a standalone Skill ZIP for local Skill-folder import.

## What problem it solves

Automated security fixes often contain a persuasive summary and a passing scanner rerun. Reviewers still need to establish that every alert maps to the reviewed diff, the validation ran against the same commit, behavioral regressions are covered, and unrelated dependency or permission changes are understood. The Skill standardizes that review without claiming access to GitHub or replacing repository policy.

## Intended users and use cases

- application-security teams reviewing agent-generated remediations;
- repository maintainers receiving one or many code-scanning fixes in a draft pull request;
- engineering leads defining a consistent human approval record;
- auditors reconstructing why a security-fix change was allowed or blocked.

Use it for GitHub agentic autofix, another coding agent, or a manually prepared remediation packet. It is especially useful when a single pull request covers multiple alerts and partial success must remain visible.

## Implemented features

- one row per alert with rule, severity, location, changed paths, fix mechanism, evidence, and verdict;
- evidence states: observed, reported, missing, and not applicable;
- separate scanner, behavioral, human-review, and deployment gates;
- focused checks for dependencies, workflows, permissions, generated files, secrets, configuration, and migrations;
- bounded overall verdicts: `ready`, `ready with changes`, or `blocked`;
- required human reviewer, rollout owner, observation signal, and rollback action;
- deterministic installer, standalone Skill, source archive, and SHA-256 generation.

## Prerequisites

- A pull request review packet containing the diff or changed-file details, alert metadata, check results, and available test evidence.
- iPolloWork 0.50.12 or later for the packaged installer. The Skill itself has no runtime, account, network, or external-service dependency.
- A model capable of reading Markdown and the supplied project files.

## Inputs and outputs

Input may be Markdown, pasted text, exported JSON, local files, or a combination. Include the base branch, reviewed head commit, alert IDs, changed paths, scanner result, behavioral tests, review state, human owner, rollout observation, and rollback plan when available.

Output is an eleven-section Markdown review containing the overall verdict, boundary, alert-to-change matrix, evidence ledger, patch and validation assessments, scope-risk gates, required actions, merge checklist, residual risk, and advisory boundary.

## Workflow

1. Gather the PR diff, alert list, check results, tests, and ownership data.
2. Ask the model to use `autofix-merge-gate` and review the packet.
3. Confirm the report uses the reviewed head commit and preserves every alert ID.
4. Resolve blocking actions and rerun the review with the new evidence.
5. Let the repository's branch rules and security owner make the actual merge decision.

## End-to-end example

Use [examples/review-packet.md](examples/review-packet.md):

```text
Use the autofix-merge-gate Skill to review examples/review-packet.md.
Preserve alert IDs and the reviewed commit. Return the complete merge-gate report.
```

Expected result: both alerts receive passing row-level assessments, while the overall verdict is `blocked` because the changed lockfile has no dependency-review evidence. The expected summary is in [examples/expected-review.md](examples/expected-review.md).

## Install and use in iPolloWork

1. Download `autofix-merge-gate-1.0.0.ipollowork-plugin` from the GitHub Release.
2. Open iPolloWork and select **Extensions → Plugins → Add → File**.
3. Choose the downloaded package. In the preview, confirm publisher `sykdhqk`, version `1.0.0`, one Skill, and no agent, command, MCP, permission, or authorization resource.
4. Select **Install Plugin**, then confirm the plugin and `autofix-merge-gate` Skill are enabled. Reload the project when prompted.
5. Add a review packet to your project. Start a task with: `Use autofix-merge-gate to review <packet path> and produce the complete report.`
6. Verify that the output preserves alert IDs and the head commit, gives each alert a verdict, separates scanner and behavioral evidence, and ends with the advisory boundary.

For the local Skill route, download the Skill ZIP, extract it, and choose the folder that directly contains `SKILL.md` from the local Skill import page. A GitHub repository URL is not a general file-install substitute.

## Build and package

Requires Node.js 20+ and the system `zip` utility.

```bash
npm test
npm run package
cd dist && shasum -a 256 -c SHA256SUMS.txt
```

The build creates a clean staging area. The installer contains one root manifest plus the complete Skill directory. It contains no credentials, local service, executable MCP server, native code, or nonempty permission declaration.

## Validation

Version 1.0.0 is validated on macOS 15.5 arm64 with iPolloWork 0.50.12 and the OpenCode engine. The task header showed `GPT 5.6`, but the detailed model selector continued to mark a different provider entry, so the exact model variant is recorded as unverified. Validation covers file import, preview, install, enablement, Skill and reference loading, the supplied end-to-end invocation, and disable/re-enable reload. Uninstall/reinstall, same-version update, Windows, Linux, other engines, live GitHub access, branch protection enforcement, and real CodeQL execution are outside the tested boundary.

## FAQ

**Does it merge a pull request or call GitHub?**  
No. It reviews evidence supplied in the task and returns an advisory report.

**Is a successful CodeQL rerun enough for `ready`?**  
No. The Skill also requires relevant behavioral evidence, coherent commit identity, scoped changes, human ownership, and rollback.

**Can it review a multi-alert pull request?**  
Yes. Every alert receives its own matrix row and verdict; a blocked row cannot be hidden by a passing batch summary.

**Why is a lockfile-only change reviewed?**  
Dependency and generated-file changes can expand risk beyond the stated fix. The Skill requires a reason and evidence or asks that the unrelated change be removed.
